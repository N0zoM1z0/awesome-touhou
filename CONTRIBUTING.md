# Contributing

Thank you for helping make Awesome Touhou more useful. This is a curated list, not a directory of every Touhou-related link, so every addition needs a clear reason to be here.

## Quality Requirements

Every submission must meet all of these requirements:

1. **Directly relevant**: Touhou Project is central to the resource, not a passing reference, character name, domain name, or optional theme.
2. **Useful**: The project solves a recognizable problem for players, developers, researchers, creators, or the community.
3. **Documented**: A newcomer can understand what it does and how to use it.
4. **Distinct**: It adds meaningful value beyond existing entries.
5. **Recommendable**: A contributor can explain why it deserves attention beyond popularity or GitHub stars.
6. **Legal to link**: It does not primarily distribute pirated games, music, books, or other copyrighted material.

Projects do not need a minimum number of stars. Low-profile infrastructure, preservation work, and resources from non-English communities are especially welcome when their value is well explained.

## Scope

Good fits include:

- Game launchers, compatibility tools, practice tools, replay tools, patchers, and modding frameworks.
- Reverse engineering, decompilation, preservation, and documented technical research.
- Game-development engines, libraries, formats, and source releases.
- Translation and localization infrastructure.
- Music databases, metadata tools, playback tools, extraction tools, and reusable datasets.
- Open-source fangames, substantial Touhou mods, and curated indexes of Touhou content in other games.
- High-quality multilingual knowledge bases and community utilities.

Usually out of scope:

- Personal bookmark collections, one-off exercises, and minimally documented demos.
- Projects matched only by a GitHub topic, a character name, or unrelated use of the word “Touhou.”
- General-purpose software that merely supports a Touhou-themed skin or example.
- Individual artists, music circles, streamers, shops, and isolated fan works.
- Piracy, unauthorized game downloads, asset dumps, and reuploads of copyrighted works.
- Referral links, affiliate links, advertisements, and self-promotional spam.

Tools that extract or transform data from a user's legally obtained copy can be in scope. They must not bundle or redistribute copyrighted game assets, music, books, or other original content.

## Languages

The list and all entry descriptions are maintained in English so the catalog stays consistent and searchable. Projects and resources in Japanese, Chinese, or any other language are first-class candidates: describe their documentation and interface languages accurately, and evaluate them on their usefulness rather than the contributor's or author's location.

## Forks and Successors

Prefer the original upstream project when it remains maintained and recommended. A maintained fork or successor may replace it when the original is inactive and the newer project has clearly continued the work or gained real adoption. Explain the relationship in the entry description, and avoid listing near-identical forks unless each serves a meaningfully different audience or use case.

## Historical Projects

The main list does not include inactive, archived, deprecated, undocumented, broken, or superseded projects. Resources with clear preservation, research, source-reference, or historical value may instead be documented in [Historical and Reference Projects](historical.md), with an explanation of why they remain useful.

## Entry Format

Use the canonical project name and URL whenever possible. Descriptions must be in English, concise, factual, and end with a period.

```markdown
- [Project Name](https://example.com/) - What it does and why it is useful.
```

Keep entries alphabetized within a section. Add one project per pull request so each proposal can be reviewed on its own merits.

## Pull Request Checklist

- Search existing entries, issues, and pull requests for duplicates.
- Read the project's documentation and test the resource when practical.
- Use a canonical HTTPS URL; prefer the source repository for open-source software.
- Add the entry to the narrowest appropriate section.
- Explain direct Touhou relevance, the intended users, and why the project stands out.
- Disclose whether you maintain or are affiliated with the submitted project.
- Confirm that the project does not primarily provide unauthorized copyrighted material.
- Check spelling, grammar, Markdown formatting, and alphabetical order.

Maintainers may edit descriptions, move entries, request stronger evidence, or decline projects that do not improve the list. Popularity is a signal, not an acceptance criterion.
